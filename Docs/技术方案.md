# MADSearcher 技术方案

调研日期：2026-09-08。此文档先于实现建立；开发状态以 `tasks.json` 为准。用户已确认实现目录为现有 `MADSearcherTool`。

## 1. 创作工作流与问题

MAD 是对动画、漫画、游戏等素材进行重新剪辑、合成和声音编排的同人影像。本项目只辅助找素材及分离人物，不生成完整作品、不提供下载番剧、自动配乐或通用剪辑器。

| 方向 | 创作工序与机械负担 | 工具应解决的问题 |
| --- | --- | --- |
| 剪辑向 / 节奏向 | 从多集素材寻找动作、构图、情绪一致的镜头；剪点、运动方向和节奏需要作者判断 | 分组索引、人物/场景/动作/台词搜索，保留原文件和时间段 |
| 静止系 | 漫画或立绘拆层、人物轮廓处理、背景补绘、虚拟摄影与排版 | 输出透明人物与蒙版，交给 PS/AE 合成；不冒充自动完成补绘和运镜 |
| 误解系 | 重组叙事和对白，跨作品合成；人物遮挡、发丝、特效与镜头切换造成逐帧修补 | 描述或首帧蒙版引导分割、时序传播、可检查的帧序列与 AE 路径 |

创作者一手页面采样：[一纸空谈绘成如愿以偿 / 风华回战2023](https://www.bilibili.com/video/BV1YG411S7rP/)、[被囚禁于诗中的蝴蝶 / 风华回战2024](https://www.bilibili.com/video/BV1DZYqeeEap/)、[Emotional numbness / 风华回战2025](https://www.bilibili.com/video/BV1K543zoE7S/)、[MAD剪辑及实况录制教程](https://www.bilibili.com/video/BV17s411D7Gz/)。这些页面用于理解制作语境，不以标题或封面判定质量；本次网页检索不等于完整观看视频，亦不声称取得可靠播放量排名。

## 2. 决策与可行性

| 模块 | 采用方案 | 可行性与边界 |
| --- | --- | --- |
| 桌面端 | C# / WPF，使用本机 .NET 9 SDK，轻量原生样式 | Windows 专用；可离线启动，无浏览器壳；SDK升级不影响工作区格式 |
| 处理进程 | Python 3.10+，单次命令进程，UTF-8 NDJSON 标准输入输出 | C#负责生命周期和取消；不开放本地HTTP端口，API密钥不放命令行 |
| 媒体 | FFmpeg / FFprobe 参数数组调用 | 元数据、采样、标准化预览、PNG序列、ProRes4444；不改原视频 |
| 素材库 | Python sqlite3（WAL、外键、事务），文件路径引用 | 一个动画一个分组，重复导入检测，保留索引状态；无需单独数据库服务 |
| 字幕 | SRT / ASS / VTT解析，UTF-8及常见中文编码 | 支持外挂字幕、时间偏移、排除样式标签；纯字幕搜索无需云服务 |
| 语音识别 | faster-whisper，本地多语言ASR | 默认CPU/int8与small模型，可切CUDA；首次模型下载需网络，不保证专名和歌词准确 |
| 视觉语义 | OpenAI Responses图像理解，多张采样帧与相邻字幕组成片段描述 | API key按需求留空。用户启用AI索引后才发送采样图和文字；不上传整部视频 |
| 语义检索 | 描述与字幕的embedding + 关键词匹配 | 中文场景/情节可以跨语言检索；未做视觉索引时明确显示仅字幕能力 |
| 人物辨识 | 可空角色资料与参考图，Responses返回稳定角色ID、视觉依据及采样帧关联 | 仅视觉索引判断出镜；支持姓名/别名查询关联，证据不足保留未知，medium显示待确认 |
| 图像边界与观测 | Pillow按用途处理：索引长边512，抠像定位保留原尺寸；索引按模块记录JSONL与耗时汇总 | 本地SAM原图不变，模型token以实际usage为准，阶段自身耗时避免重复计入子步骤 |
| 视频抠像 | SAM 2.1 tiny，本地分割与视频传播 | 可接首帧蒙版或框提示。动画特效、半透明和大遮挡不保证完美，必须预览检查 |
| 描述/参考图提示 | OpenAI视觉先定位首帧目标框，再交SAM2 | 定位与精细轮廓职责分离；目标必须出现在片段首帧，定位失败明确停止 |
| 创作输出 | RGBA PNG、灰度mask、ProRes4444 MOV、AE三种JSX交接 | 默认完整原画＋Alpha修补遮罩，另有直接RGBA及可选矢量路径；保留现有像素，单次撤销组 |
| PSD序列 | 暂不实现 | 写可靠PSD矢量路径/图层蒙版且跨PS版本验证代价高，PNG+mask及AE路径满足主要交接 |

本机：Windows、.NET SDK 9.0.317、Python 3.10.11、FFmpeg 7.1.1；NVIDIA RTX 3060 Laptop 6GB。部署采用项目内虚拟环境，不修改全局Python。基础依赖与AI依赖分开，SAM权重不进入Git。显存有限，短片段优先、CPU帧缓存、模型tiny；超长抠像要求先裁短。

不采用逐帧独立背景移除作为主方案：缺乏目标身份约束与时序一致性。不把CLIP单帧相似度作为唯一检索器：专名、对白和情节需要文字上下文。暂不引入向量数据库服务：个人动画库的SQLite持久化和本地向量排序更易安装维护。

## 3. 数据与费用

原素材保留原位；数据库、缩略图、预览、导出、临时任务和模型均位于项目 `workspace/` 或 `models/`。按v0.1.0后的用户反馈，WPF设置中的key改为随设置明文保存在被Git忽略的本地文件中，重启恢复；配置默认值仍为空。启用云处理的界面清楚说明将发送采样帧、字幕、已保存的角色资料/参考图或查询。模型名可配置，默认候选 `gpt-4.1-mini` / `text-embedding-3-small`，权限与可用性由实际API返回判断。使用 `store:false`；处理云端拒绝、格式错误、429和超时，不伪造成功。

默认本地检测镜头切换，超过20秒的长镜头继续细分，按时长与变化动态采样1–6张；保留固定时长模式（默认8秒），索引保留窗口起止和原始来源。结果只用于定位，边界可以由用户修改。索引可重做，但完整替换必须在新结果成功后事务提交，避免失败毁掉旧结果。

## 5. 角色资料扩展（2026-09-12）

采用独立角色表和片段关联表，首次版本迁移前备份旧库。每段直接对照该组全部非空角色资料和参考图，无额外模型预筛选步骤；索引外发图片统一512像素（抠像定位保留原尺寸），前缀组织便于可能的服务端缓存，不能保证费用下降。每次索引落地阶段日志、独占/包含耗时和实际API usage。详细技术路线、输入结构、完整提示词与后续扩展边界见[专项说明](角色索引技术路线与提示词.md)。

## 6. 抠像时间线与缓存预览（反馈7）

用户接受第一次定位等待，采用桌面侧只读FFmpeg持续解码、rawvideo BGRA管道及WPF有界缓存。预取约5秒、保留已播放约2秒，缓存内即时取帧，连续播放沿用解码进程；缓存外远跳允许从头解码等待。原画与RGBA结果分别可折叠，无声播放，使用同一可复用时间线控件设置帧级起止。每面板128MiB缓存像素预算，长边最多640的预览副本不改变原图和SAM输出。模块、取消和范围合同见设计文档第13节。

## 7. 姓名查询与排序（反馈13）

查询时从当前分组资料提取句内姓名/别名，生成原句、去名情节和已填外观描述三路文本，复用现有向量索引。组合查询以情节为主，原句/外观允许低权重补充召回，人物证据最多占总分10%；多路排名用RRF融合，避免直接混加不同通道的原始分数。纯人物查询使用角色关联及姓名文字提及，不请求embedding。最多三条去重查询合并一次向量批次，并采用有界本地缓存；没有新增视觉调用或索引重建。详细规则及工程阈值见[姓名查询与排序](姓名查询与排序.md)。

融合方法参考[Azure AI Search的RRF说明](https://learn.microsoft.com/en-us/azure/search/hybrid-search-ranking)。本项目的70/20/10权重和召回门槛是待实际素材验收的工程初值，不代表该来源推荐这些具体参数，也不代表识别准确率。

## 8. 独立台词索引与搜索模式

字幕与画面拆开建向量：字幕单条及同类相邻2–3条短上下文独立保存，保留原始时码。字幕文字和字幕语义独立召回，完整原文优先；综合模式再与已有场景路线按排名融合，台词模式不按角色字典改写原句，画面情节模式沿用原检索。数据库版本3独立字幕表及文件缓存支持只补台词；改变人物资料不使字幕索引失效，完整索引原视觉缓存保持兼容。不调用新的精排模型。细节见[台词检索与补建](台词检索与补建.md)。

ASS/SSA先按绘图状态提取可见文本，再去重同时间显示层和保守合并连续特效。20000条约束针对清理、分行、去重后的有效字幕，不针对原始显示事件。独立台词来源记录 `subtitle_cleanup_version`，仅旧ASS/SSA台词需显式补建；完整索引与仅台词补建共享解析逻辑，日志输出数量统计及解析耗时。SRT/VTT、ASR和已有视觉索引不因这项变更统一失效。

## 9. AE三种导出（反馈14）

默认matte保留完整source_frames，将已有RGBA的Alpha通道用于独立遮罩预合成，包含锁定底稿及空的补回/去除层。rgba直接导入透明PNG；paths保持逐帧HOLD矢量近似，4096点/轮廓、64轮廓/帧、100万累计顶点的保护阈值不影响前两种像素方式。矢量失败时保留并提示实际使用matte脚本，不靠继续简化原始轮廓通过导出。

cutout.export_ae从完整任务manifest和现成PNG补导出，不加载SAM、解码视频或调用模型。每次新增独立ae_exports目录和报告/日志，旧数据不变。JSX模板统一处理相对路径、原尺寸/帧率合成、Straight Alpha、修补图层、当前合成插入与单次撤销，不保存用户工程。具体操作见[AE导出与修补](AE导出与修补.md)；代码构建完成不代表已进行Adobe实际验证。

2026-09-15的脚本第二版将用户入口整理为整体边缘控制及彩色局部修补，对外仍为一个人物合成。补回层使用已有完整原画，去除层保留Silhouette Alpha；合并后的Alpha依次经过Simple Choker、Gaussian Blur 2，再交给完整原画输出颜色。两个滑块默认0，不预设柔化或收缩。使用原生效果matchName及参数合同检查，不依赖界面翻译；当前合成内表达式连接控制值，功能不依赖外部插件。说明依据：[Adobe遮罩效果](https://helpx.adobe.com/ca/after-effects/desktop/apply-effects-and-animation-presets/list-of-effects/matte-effects.html)、[模糊效果](https://helpx.adobe.com/cn/after-effects/desktop/apply-effects-and-animation-presets/list-of-effects/blur-sharpen-effects.html)、[效果matchName](https://ae-scripting.docsforadobe.dev/matchnames/effects/firstparty/)。原脚本/AE工程不自动迁移，需显式补导出；控制表达式和最终像素一致性仍待AE验收。

## 10. 存储管理（反馈15–17）

把索引依赖的缩略图与可清理的采样图分开：Store提交新索引前按内容摘要原样复制到workspace/thumbnails，保持原索引配置和数据库版本3。旧索引在用户清理时先复制图片、再事务更新引用，成功后才删缓存；不会重建索引或请求模型。清理依据明确目录白名单、数据库引用和任务结果标记，保留所有已完成或未完成任务输出。

storage.scan给出容量与计划摘要令牌，storage.clean重新验证后执行；Windows共享/独占[LockFileEx活动锁](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-lockfileex)协调新版GUI和CLI，不阻塞正常浏览任务之间的并发。删除不跨目录链接，每个文件复核元数据，只回收受管空目录。界面提供清理范围确认及打开实际索引目录入口，具体保留范围、成本和失败处理见[缓存清理与索引资源](缓存清理与索引资源.md)。
