# 镜头分段与动态采样

更新：2026-09-13。对应优化清单第11项，代码位于dev；功能测试按用户要求延期。

## 使用

在片段检索左侧的索引选项中选择“按镜头切换（推荐）”。默认灵敏度为中、长镜头上限20秒。切分太碎可选低灵敏度，漏掉明显切镜可选高灵敏度；更改后重新建立索引。保留“固定时长”模式，默认8秒，可用于比较或无需镜头检测的字幕索引。时长可填写2～60秒。

首次按镜头索引会顺序扫描视频，再提取需要的采样图片。界面显示检测位置与采样进度，进入视觉分析前显示本次预计请求数、采样图和参考图累计数量。不自动请求确认，不增加任务队列；取消会结束处理，之前已经提交的索引仍保留。

镜头索引的相邻命中默认分开显示，同一长镜头内部的相邻子段可以合并。选中结果后，“扩展前后镜头”将起止范围扩展到前后各一个镜头，包括没有字幕、没有命中的相邻镜头；“恢复命中范围”恢复原范围。范围扩展不改变分数和人物出镜证据，需点击“生成 / 更新预览”查看。扩展总范围超过5分钟时提示手动调整。

CLI例子（ID替换为库中真实ID）：

```powershell
.\MADSearcher-CLI.cmd index.run --video-id VIDEO_ID --subtitle-path 'E:\素材\第1集.srt' --segmentation shot --shot-max-seconds 20 --scene-sensitivity medium --visual
.\MADSearcher-CLI.cmd index.run --video-id VIDEO_ID --subtitle-path 'E:\素材\第1集.srt' --segmentation fixed --segment-seconds 8
```

第二条只建立本地字幕关键词索引；需要语义向量时另加 `--semantic`。只传旧参数 `--segment-seconds` 仍按固定时长处理，完全不传分段参数时默认按镜头。接口新增 `shot_plan` 和 `image_estimate`，现有结果字段继续保留。

## 技术路线

```mermaid
flowchart LR
    A[只读原视频] --> B[FFmpeg逐帧缩图与PTS]
    B --> C[本地AdaptiveDetector切镜]
    C --> D[过滤短闪光与细分长镜头]
    D --> E[按时长和画面变化采样]
    E --> F[字幕归属与角色视觉分析]
    F --> G[语义向量]
    G --> H[事务替换索引]
```

- 检测使用PySceneDetect 0.6.6的AdaptiveDetector。锁定该版本的帧号接口，它可复用已有opencv-python-headless，且不限制现有语音识别环境的Click版本。项目环境已安装依赖；重新部署运行 `scripts/setup.ps1` 即可安装基础依赖。
- FFmpeg保持每个解码帧，检测副本长边最多320像素。rawvideo与showinfo通过有界队列配对；保存解码帧序号与实际PTS，首帧作为时间零点。实际切点不以平均帧率换算，末端时长采用媒体元数据并保底覆盖末帧。
- low/medium/high分别使用自适应比值4.0/3.0/2.2和内容变化下限20/15/10。允许短镜头，仅过滤不超过0.25秒的极亮/极暗变化且前后小图相近的闪光。检测器末尾补足观察窗口，但不会把补帧计入素材或索引。
- 同一镜头超过上限后等分，再对齐实际帧时间，边界最多存在一帧的量化差异。保存父镜头ID、父镜头范围与子段帧范围；不创建实体视频切片。
- 第二次顺序解码只将缺失的采样帧保存为JPEG，长边最多512；已经存在且能通过图像文件完整性检查的采样文件复用。固定模式沿用按时间取帧，也缓存512像素副本。原视频、角色参考原图和抠像策略均不改写。

采样起点规则如下，后续做保守图像去重，至少留一张：

| 片段时长 | 采样数量 |
| --- | --- |
| ≤2秒 | 1张 |
| >2～5秒 | 2张 |
| >5～10秒 | 3张 |
| >10秒 | 4～6张，随时长及画面变化增加，上限6 |

镜头模式在多个时间区间内选图，避开边界最多0.15秒；优先考虑区间中心附近有变化的画面，对全黑/全白画面降权。非常短的镜头按实际可用帧数取样。RGB缩略图平均像素差小于1.5/255的近似重复图片只保留一份。这是图像相似度判断，不是人物身份判断；小动作仍可能漏掉。

## 缓存与数据升级

| 位置 | 内容与失效条件 |
| --- | --- |
| `workspace/cache/shots/<video>/<key>/detection.json` | 帧时间、变化/亮度指标、切点；取决于素材指纹、解码器路径、算法版本和灵敏度 |
| `workspace/cache/samples/<video>/<key>/` | 本地采样JPEG；取决于检测结果、分段/采样策略和视觉开关，与角色资料无关 |
| `workspace/cache/analysis/<video>/<key>.json` | 每个片段的描述、角色证据和向量；取决于素材、范围、采样时间/帧、字幕、作品和角色资料、模型及提示词/图像策略 |
| `workspace/cache/index/<video>/<key>/checkpoint.json` | 当前完整索引配置的进度及已生成字幕，用于中断恢复 |

调整长镜头上限后，边界和采样未变化的片段可复用已有模型结果。修改角色资料后仍复用检测与采样，但视觉分析需要重做；本次不增加专门的人物身份模型。旧版本3索引可继续查询，主动重建时使用版本4规则，不直接套用旧AI检查点。旧缓存暂不自动清理。

SQLite的user_version升级为2：增加shots表、segments.shot_id与metadata。升级前自动备份到 `workspace/backups/library_before_shots_*.sqlite3`；新增结构和版本更新在事务内完成。shots独立保存所有镜头范围，避免无字幕镜头丢失，也避免把整份镜头列表复制到每个检索段中。

## 提示词与费用

完整固定提示词见[角色索引技术路线与提示词](角色索引技术路线与提示词.md)，当前版本 `character_shot_v2_timestamps`。新增规则说明采样数量可变、图片不一定等间隔，禁止把某个采样时刻的出镜推断为整段始终出镜。动态输入附带实际范围与采样位置，例如：

```json
{"clip_range_seconds":[20.0,24.0],"samples":[{"frame_index":0,"source_seconds":21.0},{"frame_index":1,"source_seconds":23.0}]}
```

上面的数值仅为格式示例。角色的frame_indices仍从0开始，只指向本段采样图片；参考图不是镜头画面，字幕点名也不构成出镜证据。角色候选、未知/重复ID校验和当前检索评分规则保持原有约束。

每次视觉请求的图片数为本段采样数N加参考图数R。镜头更短会增加请求次数，动态采样不能保证总费用下降。估计数字不含网络重试；实际token、缓存token及重试次数以日志为准。没有开启视觉时，不发送任何图片；只开启字幕语义时仅发送文字。

## 日志与验证状态

新增阶段：`media.shot_detection`、`shots.cache_read/write`、`shots.plan`、`media.index_samples`、`samples.cache_check`、`samples.deduplicate`、`analysis_cache.read/write`。原有视觉、图像处理、embedding、ASR、数据库与检查点耗时继续记录。

`shot_plan`事件包含镜头数、片段数、时长最小/中位/最大值、候选采样数和过滤闪光切点数；`index_estimate`包含完整计划和扣除缓存后待发送的图片/请求数。summary.counters包含这些数量与各层缓存命中数。逐段视觉日志增加shot_id、sample_count、sample_times。密钥、完整提示词、字幕和图片不进入日志。

当前只做语法/静态检查、依赖检查和WPF构建发布。已维护待执行用例覆盖可变时间戳、短镜头、长镜头连续分段、缓存损坏、跨镜头结果和未变化片段缓存复用。没有执行视频解码、数据库迁移、界面、模型或回归功能测试。切镜准确度、闪光/叠化、长视频吞吐及角色识别效果等待后续素材验收。

补充：固定模式记录的是请求取帧时刻，实际返回帧按解码器定位；镜头模式记录逐帧解码PTS。每个新完成片段单独落盘，总检查点每32段或末段汇总，取消后仍可从片段缓存恢复。
