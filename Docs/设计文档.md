# MADSearcher 设计文档

版本1；先确定合同与边界，随后按DAG开发。所有相对路径以仓库根目录为基准。

## 1. 结构

`src/MADSearcher.Desktop/`：WPF窗口、状态、输入校验、Python进程客户端。
`worker/mad_worker/`：CLI、媒体核心、素材库检索、抠像及输出。
`tests/`：核心逻辑和真实FFmpeg集成测试；不依赖用户私有素材。
`scripts/`：安装、启动、发布、DAG校验及状态工具。
`Docs/`：方案、设计、协议、验收与使用说明。
`.agents/skills/`：本项目真实复现问题的恢复经验。

运行时的 `workspace/`、`.venv/`、`models/`、`artifacts/` 不入Git。默认全在项目目录，原素材只读。

### 命令行补充设计（按新增需求）

`scripts/cli.py` / `MADSearcher-CLI.cmd` 提供与worker命令同名的参数化入口，例如 `group.create --name MyGO`、`search.run --group-id ID --query 祥子`。全部核心命令共用原有处理模块与校验，不另写检索或模型逻辑。每条命令支持 `--params-file` 读取JSON参数；`request --request-file 文件` 接受完整原始请求，`-` 表示stdin。stdout仍为NDJSON，进度/结果/错误语义不变。

CLI 默认读取GUI设置及已保存的密钥，支持独立 `--settings` JSON及命令参数覆盖；密钥优先使用显式存在的 `OPENAI_API_KEY` 环境变量，原始请求可由stdin传递。不提供会进入进程列表的 `--api-key` 参数，CLI不改写设置文件。Ctrl+C中断当前处理。新增 `ae.send` 服务仅验证路径并把已生成JSX交给 `AfterFX.exe -r`；结果明确区分已派发与AE执行完成。AE动作只有用户显式调用该命令时执行，当前不测试此动作。

## 2. 进程协议（模块间合同）

执行 `python -u -m mad_worker`，工作目录为 `worker/`。stdin只有一行JSON后关闭；stdout每行一个事件；第三方输出必须导向stderr。请求包含：

```json
{"command":"group.list","params":{},"settings":{},"workspace":"E:/MADSearcher/MADSearcherTool/workspace"}
```

事件：`{"type":"progress","progress":0.5,"message":"说明"}`、`{"type":"result","data":{}}` 或 `{"type":"error","code":"validation","message":"中文可操作说明"}`。进程退出0对应成功；非零失败。取消由父进程终止整个子进程树，UI保持响应。无命令行key，无日志回显key。

统一 settings：`ffmpeg_path`、`ffprobe_path`（默认命令名）；`api_key`（空）、`vision_model`（gpt-4.1-mini）、`embedding_model`（text-embedding-3-small）；`sam_checkpoint`（空）、`sam_config`（configs/sam2.1/sam2.1_hiera_t.yaml）、`device`（cpu/cuda）；`whisper_model`（small）、`whisper_device`（cpu）。WPF本地设置另含 `python_path` 和 `workspace`。

Python共享 `Context`：`workspace: Path`、`settings: dict`、`media: Media`、`progress(value,message)`；业务异常 `UserError(message, code="validation")`。所有模块入口 `handle(command, params, ctx) -> dict`。

媒体合同 `Media(settings)`：`probe(path)->{path,duration,width,height,fps,fps_rational,frame_count,has_audio}`（frame_count可为空）；`extract_frame(path,seconds,output)->str`；`extract_frame_index(path,index,output)->str`；`extract_frames(path,start,end,fps,directory)->list[Path]`；`make_preview(path,start,end,output)->str`；`run(args,timeout=...)->CompletedProcess`（args为ffmpeg开关，方法自动前置ffmpeg）；FFmpeg数组参数，禁shell拼接。

| command | params | result.data |
| --- | --- | --- |
| system.check | 无 | checks数组（name,ok,message），python版本 |
| group.list | 无 | groups:[{id,name,description,video_count,segment_count}] |
| group.create | name,description | group对象 |
| group.update | group_id,name,description | group对象 |
| group.delete | group_id | deleted:true（仅库记录） |
| video.list | group_id | videos:[{id,path,name,duration,width,height,fps,status,subtitle_path}] |
| video.add | group_id,paths:[] | videos数组，warnings数组（重复提示） |
| video.remove | video_id | deleted:true（仅库记录） |
| index.run | video_id,subtitle_path可空,subtitle_offset:0,transcribe:false,language:"auto",visual:false,semantic:false,segment_seconds:8 | segment_count,video_id,mode,warnings |
| search.run | group_id,query,limit:20,semantic:false | results:[{video_id,path,name,start,end,text,score,thumbnail,match_type}],warnings |
| video.probe | path | 媒体元数据 |
| video.frame | path,time:0，或frame_index（从0起，与time互斥） | path（缓存PNG）,width,height,frame_index（按帧请求时） |
| preview.make | path,start,end | path（缓存H264 MP4） |
| clip.export | path,start,end,output_dir | path（独立MP4） |
| cutout.range | path,start/end（秒或MM:SS:FF），或start_frame/end_frame（终点不含；与start/end互斥） | video, start_frame,end_frame,start,end,start_timecode,end_timecode,frame_count,fps,fps_rational,nominal_fps,total_frames,total_frames_estimated |
| cutout.run | path,与cutout.range相同的范围参数,prompt_mode:mask/text/reference/box,mask_path,prompt,reference_path,box:[x0,y0,x1,y1],output_dir,export_video:true,export_ae:true | 范围字段（同cutout.range，不含video）,output_dir,preview_path,rgba_dir,mask_dir,video_path,ae_script,manifest_path,warnings |
| ae.send | script_path；settings.afterfx_path | dispatched,pid,script_path,message（仅确认派发） |

box为首帧原图像素坐标；mask是所选片段首帧对应的同尺寸透明PNG或黑白图。text和reference要求key，mask和box完全本地。字幕index先解析整个文件并按真实时间聚合，ASR仅无外挂字幕且用户勾选时执行。GUI可以批量逐视频索引，单个请求只负责一个视频。索引仅在 `visual` 或 `semantic` 明确开启时调用 OpenAI；仅填写密钥不会触发云端处理。视觉索引同时建立向量，字幕语义索引仅发送文字。`video.list` 从已保存索引配置返回 `subtitle_offset`。

## 3. 用户界面

遵循需求草图：顶部通用菜单和项目状态，左侧“片段检索”“自动抠像”，左下设置，右侧功能工具条与主区。中文界面，深色中性底、青绿色强调，明确空状态和步骤提示。

检索页：分组选择/新建/编辑；素材列表批量导入与选中；字幕绑定、字幕偏移、ASR语言和视觉索引选择；索引进度/取消；查询框和语义开关；结果卡片（缩略图、原文件、时间、命中说明）；预览播放器、起止可调、导出片段或送抠像。

抠像页：视频选择与探测；起止分钟:秒:帧（兼容小数秒输入）；首帧查看；模式选择；蒙版/描述/参考图输入；可选像素框；导出目录、MOV/AE选项；运行进度和可取消；结果预览、打开输出文件夹。PSD明确“暂不支持”。没有可用SAM checkpoint时给出安装指引，不执行空任务。

设置：Python/FFmpeg路径、运行目录、OpenAI密码框和模型、SAM权重及配置、CPU/CUDA、Whisper模型；环境诊断；设置与密钥按用户要求明文保存在本地，重启恢复；运行中可保存其他设置，但当前任务继续使用快照。

## 4. 数据与一致性

SQLite外键约束groups→videos→segments。原路径规范化后同组唯一，视频文件大小和mtime作为变化探针。字幕/模型配置变更需要重新索引。索引失败显示失败原因、保留上一次可用数据，不能把一半结果标记完成。按group_id过滤每次搜索，无全库混搜。结果同视频邻接片段适度合并，时间裁到[0,duration]。缩略图与预览缓存均由内部生成的名称定位。

字幕台词词法检索为无key的实用基础；语义搜索要有已建向量，缺失时显示降级原因。不要把substring冒充AI。人物姓名依赖字幕和分组上下文，模型不确定时保留外观描述。

抠像任务单独目录，先写中间产物，完成时写manifest。manifest版本2记录原视频、源起止帧号、规范时间码、名义秒数、fps及有理数帧率、尺寸、模型、输出与警告，不含key。按解码帧序选取半开范围并保留每帧，源VFR输出为平均帧率CFR并提示，不保留原生时间戳。默认短片段，上限120秒/3600帧，SAM2默认32帧一块，以重叠首帧蒙版衔接，释放块状态，CPU缓存帧。分块会有时序边界误差，输出中明示。轮廓导出是像素mask近似，采用HOLD关键帧避免不同顶点数的插值错误；复杂孔洞与遮挡处理需验证，PNG为最终像素依据。

## 5. 校验与错误

GUI和worker均校验：空名称、重复分组、未选素材、不存在/无视频流/损坏文件、非有限时间、媒体片段end≤start或字幕end<start、越界时间、超长任务、蒙版尺寸与前景为空/全画面、输出目录可写且不覆盖输入、缺权重、缺依赖、未配key、未知模式/命令。禁止用户继续非法步骤；worker错误为具体修复说明。按钮在运行中禁用重复提交；取消终止子进程，旧索引和原文件不变。所有数值采用InvariantCulture传输。

## 7. v0.1.0 后的易用性修正设计

字幕允许 `end == start`，仍拒绝倒置和非有限时间。零时长条目作为一个时间点参与所在的 `[窗口起点, 窗口终点)` 索引，包括0秒及窗口边界；字幕在视频范围外仍按既有规则排除。视频裁剪、预览和抠像的时间范围继续要求正时长。

按用户最新要求，API Key随“保存设置”明文写入被Git忽略的 `workspace/settings.json`，重启时恢复；CLI业务命令读取同一设置，显式存在的 `OPENAI_API_KEY` 优先（空值可以清除本次调用的key）。key仍不进入命令参数、日志、缓存或manifest。保存key不会自动启用云处理。此规则替代此前的仅会话保留限制。

运行中只禁止新增处理任务的入口，以及会触发素材库读取的分组切换和工作区切换。导航、现有结果/素材选择、滚动、播放、其他表单编辑、配置保存和打开已生成文件继续可用。每次任务开始时复制设置并捕获参数，批量任务的后续步骤也使用同一份快照。异步预览/首帧结果只有在相关选择和时间范围未变化时才应用到界面，避免旧结果覆盖新输入。没有任务队列；阻止的操作不会自动排队。继续只进行静态核对和编译发布，功能测试仍延期。

## 8. 结果滚动与帧精度（2026-09-12）

仅处理本地反馈第5、6项；角色映射、抠像时间线编辑器/双预览及自动预览仍待讨论，不在本次范围内。

匹配镜头列表使用像素滚动，保留虚拟化和容器回收，避免滚轮按多条高卡片跨越。依据 [WPF ScrollUnit](https://learn.microsoft.com/en-us/dotnet/api/system.windows.controls.virtualizingpanel.scrollunit) 设置 `VirtualizingPanel.ScrollUnit=Pixel`，不改动查询条数或排序。

抠像时间使用 `MM:SS:FF` 非丢帧时间码，分钟可超过59，秒范围0–59，帧编号从0起且小于标称帧率（实际帧率向上取整，例如24000/1001使用24）。时间码首先转为整数帧号，起点包含、终点不包含。CLI保留小数秒输入并四舍五入到最近帧，也支持显式 `start_frame/end_frame`，两种范围表示不能混用。单帧可表示为 `00:00:00` 到 `00:00:01`。23.976fps下时间码一分钟为1440帧，实际时长约60.06秒；不把时间码误当墙钟时间。

新增共享 `timecode.py` 负责解析、格式化、帧率与边界校验；`cutout.range` 只探测并解析范围，返回元数据、规范时间码、帧号和帧数供WPF/CLI使用。`video.frame` 增加 `frame_index`；抠像和首帧采用同一源视频解码帧编号。FFmpeg使用 [trim的start_frame/end_frame](https://ffmpeg.org/ffmpeg-filters.html#trim) 选择 `[起点,终点)`，显式保留每一选中帧，不再通过秒数seek和fps滤镜决定抠像首尾。严格核对实际输出帧数；缺帧视为失败。定位较后帧需要顺序解码前面的画面，首帧读取可能较慢。

优先使用媒体元数据的帧数；缺失时按时长×平均帧率估计，界面说明该估计，实际解码再次校验。VFR源也按解码帧序选择，输出仍以平均帧率组织为CFR，不保留原生可变时间戳；manifest记录准确源帧号及名义秒数。120秒/3600帧及其余抠像限制保留。界面在异步解析后仅对未改动的选择回填时间码，保留已实现的任务输入快照。只编译发布，功能测试仍延期。
