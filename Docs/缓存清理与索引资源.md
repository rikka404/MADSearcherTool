# 缓存清理与索引资源

适用于2026-09-14之后的dev实现。当前只完成静态核对和编译，实际清理、旧缩略图迁移和界面验收按用户要求延期。

## 从界面清理

1. 等待当前索引、抠像或其他处理任务结束。
2. 点击顶部“工具 → 删除缓存…”。程序先扫描容量，不删除文件、不创建或升级索引数据库。
3. 确认框列出各类候选文件数量、大小、旧缩略图迁移数量及保留项。旧缩略图需要先复制，候选删除大小不等于净释放空间。
4. 确认后，程序关闭搜索临时预览和当前结果列表，先保护旧索引图片，再清理缓存。完成提示显示实际删除数量、净释放空间、迁移和跳过情况。
5. 重新搜索即可使用原索引。搜索结果列表只是界面显示，清空列表不会删除数据库中的索引。

取消确认框不会迁移图片或删除文件。执行中取消会停止后续操作，已经删除的缓存不会恢复；索引引用只在所需图片全部复制成功后，用一个数据库事务更新。图片复制中断可能留下没有被引用的副本，下次清理可以回收。

## 清理范围

| 位置 | 内容 | 删除后的影响 |
| --- | --- | --- |
| 当前工作区/cache | 查询和字幕向量副本、镜头检测、采样、分析检查点、取帧及预览 | 已完成的数据库索引不变；后续查询、预览或重建可能需要重新计算、抽帧或调用模型 |
| 当前工作区/logs/index | 历史索引诊断与耗时记录 | 无法再次分析这些历史任务 |
| 当前工作区/backups | 程序保存的数据库升级备份 | 失去对应恢复点，当前数据库不受影响 |
| 项目/artifacts/wheels | 依赖安装包 | 已安装功能不变，重装时可能重新下载 |
| 项目/models/pip-cache | pip下载缓存 | 已安装模型和依赖不变，重装时可能重新下载 |
| 当前工作区/thumbnails中的无引用受管文件 | 旧索引替换/移除后遗留图片、被中断的复制临时文件 | 仅回收没有被当前索引或其他受保护输入引用的内部命名文件 |

清理只访问这些明确位置，不遍历整块磁盘查找`.bak`或其他“看起来像备份”的文件。运行时`.venv`、模型权重、Whisper模型、设置和API Key均保留。清理某个工作区不会遍历其他工作区；两项安装下载缓存属于当前项目，确认框显示项目位置。

## 永久保留的结果

- `library.sqlite3`及其WAL/SHM：分组、素材、场景描述、角色关联、字幕、语义向量和时间范围。
- 正在被索引引用的`thumbnails`图片。
- 角色参考图、数据库记录的源视频和字幕路径；当前界面已选择的蒙版、参考图、输入及结果路径。
- `exports`下的结果，以及清理范围内带有`manifest.json`、`INCOMPLETE.txt`或标准抠像结果子目录的任务。**未完成任务也保留**。
- 工具生成的独立片段MP4结果；抠像任务中的`source_frames`、`rgba`、`masks`、MOV、AE脚本、报告及日志均随任务保留。

如果用户将输出目录选在cache下，程序会识别标准任务结构和片段输出文件名加以保护。仍建议把正式输出放在独立的exports目录。外部软件自行生成、改名且未登记引用的文件无法可靠判断用途，不应手动存放在可清理缓存目录中。

## 缩略图和旧索引

以前，数据库可能直接引用`cache/index`或`cache/samples`中的图片，因此不能直接在文件管理器中清空cache。

现在，新索引提交前会把代表缩略图原样复制到`workspace/thumbnails`，使用文件内容的SHA-256摘要命名。数据库引用这个永久副本，采样图仍可随缓存清理。复制不缩图、不重新编码，不修改采样配置、视觉提示词、向量或索引版本。

对已有索引，第一次清理按如下次序处理：

1. 读取当前数据库的图片引用，检查目录边界、图片格式和完整性。
2. 将仍在cache中的有效缩略图复制到thumbnails；相同内容复用已有副本。
3. 全部复制完成后，用一次事务更新相关片段的缩略图路径，片段ID、文字、时间和向量保持原值。
4. 重新读取引用集合，再删除不需要保留的缓存。

迁移失败时不会进入删除阶段。磁盘空间不足时可能需要先在其他位置腾出空间，因为迁移先复制、后删除。原本已经缺失的缩略图会单独报告，程序不会凭空恢复图片，也不会为了清理自动调用模型或重建索引。不能安全处理的链接图片或仍作为其他输入使用的缓存图片会保留。

删除`cache/query_vectors`或`cache/dialogue_vectors`**不需要重新建立已完成的索引**：正式索引向量在SQLite数据库中，缓存用于查询输入、重试和重建复用。只有后续任务缺少可复用向量时才重新请求接口。

## 打开索引目录

点击“工具 → 打开索引目录”，文件管理器会打开当前工作区并选中`library.sqlite3`；数据库尚不存在时仅打开目录。`thumbnails`也在此目录下。此入口不迁移数据库，不修改设置，不启动索引任务。

## 并发、占用和异常

清理前的扫描令牌包含文件清单/大小/修改标记及数据库引用快照。确认后如果缓存或引用已经改变，程序要求重新扫描，不使用过期计划删除新文件。

普通worker取得共享活动锁，可同时完成已有浏览操作；清理取得独占锁。有另一个新版桌面窗口或CLI任务运行时，清理会提示稍后重试。不要让不支持活动锁的旧版本程序同时操作同一工作区。工作区中的`.activity.lock`是协调文件，进程退出后系统释放锁，文件留存不代表仍有任务运行。

程序不跟随符号链接或Windows目录联接进行删除；逐文件验证白名单边界和任务标记，只移除已检查文件及由此产生的空目录。遇到被外部播放器占用或无权限的文件会跳过并显示原因，不终止外部程序，不关闭AE。

## CLI

先执行只读扫描：

```powershell
.\MADSearcher-CLI.cmd storage.scan
```

查看返回的`groups`、`bytes`、`thumbnail_migration_count`、`warnings`和`plan_token`。确认范围后，把令牌作为普通字符串参数提交：

```powershell
.\MADSearcher-CLI.cmd storage.clean --plan-token "扫描结果中的plan_token"
```

自定义`--workspace`时两次使用相同目录。可用`--protected-paths`传入额外的绝对文件或目录路径，扫描和清理须传入同一保护集合。清理结果中的`removed_bytes`是删除文件大小之和，`thumbnail_added_bytes`是新永久副本大小，`net_reclaimed_bytes`是二者差额，不代表文件系统分配簇的精确变化。CLI本身不再弹确认框，提交令牌即表示按该计划执行。
