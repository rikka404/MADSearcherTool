# AE导出与局部修补

提供三种AE交接方式，默认“原画＋独立Alpha遮罩”。像素方式直接引用已有PNG，不缩图、不重编码、不简化alpha。保真指保留当前抠像的RGB和透明度；SAM已遗漏的细节仍需人工修补。实现已接入，实际Adobe导入、修补和像素对照验收尚未运行。

## 选择方式

在“自动抠像 → 输出与交接”的“AE导出方式”选择：

| 方式 | 输出与用途 |
| --- | --- |
| 透明PNG序列 | `import_rgba.jsx`；将现成RGBA序列导入，适合直接合成 |
| 原画＋独立Alpha遮罩（默认） | `import_matte.jsx`；对外一个人物合成，内部提供彩色补回、去除和整体边缘控制，同时准备RGBA脚本 |
| 可编辑矢量路径 | `import_paths.jsx`；逐帧HOLD轮廓近似，同时准备前两种像素脚本；矢量失败时实际发送matte版本并明确提示 |

“抠像完成时生成AE导入脚本”决定本次抠像是否自动生成脚本。已有结果补导出使用同一个方式下拉框，无需开启该复选框，也无需配置SAM权重或OpenAI密钥。

前两种不进行轮廓矢量化，不受轮廓顶点数量限制。第三种保持原有0.75像素简化；每条轮廓的工具保护上限从256提高至4096点，每帧及跨帧固定路径槽最多64，总轮廓顶点最多100万。这些是本工具的资源保护阈值，不表示AE的通用能力上限。矢量化仍会二值化透明度，因此需要原始半透明边缘时请选择像素方式。

## 已有抠像结果怎样补导出

1. 启动新版程序，进入“自动抠像”，在左侧选择AE方式。
2. 在右侧结果区点击 **“从已有结果补导出 AE…”**。
3. 选择之前某次抠像目录里的 **`manifest.json`**。即使当时因269或293个顶点未能生成AE路径，只要PNG及任务记录完整，也可使用像素方式补导出。
4. 完成后查看右侧“已准备”信息，确认方式和任务来源，再点击 **“发送到 AE”**。此按钮只派发脚本，请在AE确认执行结果。

补导出不探测或解码原视频，不重新运行SAM或调用外部模型。原视频移走后，只要所需PNG序列仍完整，也能补导出。程序检查完成状态、帧号连续性、帧数、PNG尺寸和像素格式；有`INCOMPLETE.txt`的任务不能作为完整结果导出。

新导出保存在原任务的 `ae_exports/ae_日期时间_随机标识/`，旧manifest、旧脚本和PNG均保留。RGBA方式仅需`rgba`；matte需要`rgba`和`source_frames`；paths还需要`masks`，蒙版缺失或矢量处理失败时会说明原因并提供matte版本。

也可以在AE中选择“文件 → 脚本 → 运行脚本文件”，打开对应JSX。移动素材时请连同`ae_exports`、`rgba`、`source_frames`、`masks`及manifest一起移动；新脚本使用相对路径，不要单独移动JSX。原先根目录的`import_cutout.jsx`仍属于旧版导出，建议重新补导出使用新脚本。

## 在AE里微调Alpha遮罩

脚本建立原尺寸、原输出帧率的结果合成；当前有活动合成时，将结果合成放到播放头处，否则直接打开结果合成。必要时延长目标合成，不改变其帧率、分辨率或项目色彩设置，不保存工程。默认关闭导入层的运动模糊及帧混合。当前合成若使用其他帧率，会按目标合成规则取样；需要逐源帧检查时，请打开新建的原帧率结果合成。

2026-09-15起生成的第二版脚本，对外仍然只有一个 **“MAD · 人物与Alpha修补 · …”** 合成，可以像普通人物素材一样放进自己的合成。双击进入后，时间线默认只显示两个操作入口：

| 入口 | 怎么用 |
| --- | --- |
| 01 整体边缘（效果控件） | 单击选中，打开“效果控件”，调整整圈边缘柔化及收缩 |
| 02 局部修补（双击：补回 / 去除） | 双击进入，在对应图层画蒙版，直接看到补回的原画 |

内部原画层已锁定并由时间线的shy开关隐藏，但仍参与渲染。“02 局部修补”的小眼睛关闭是正常状态，它提供Alpha，颜色由内部原画提供；保持脚本生成的轨道遮罩关联即可。项目面板里的内部素材收进独立文件夹。

进入“局部修补 · …”预合成后，从上到下为：

| 图层 | 用途 |
| --- | --- |
| 01 去除区域（画添加蒙版） | 去掉残留背景、多余轮廓；优先于下方补回层 |
| 02 补回区域（画添加蒙版） | 恢复误删的手指、发梢、衣摆；该层引用完整原画，画蒙版时就能看到真实颜色 |
| 原始Alpha底稿（锁定） | 保留自动抠像的原始透明度，作为可恢复的底稿 |

选择“补回区域”或“去除区域”图层，用钢笔**另画一个闭合蒙版，模式设为“添加”**。两层都使用添加蒙版圈定修补范围；去除层自身已设置擦除Alpha的混合方式，不需要再把新蒙版设为减去。可调整新蒙版的羽化、扩展及路径关键帧。

两层各有一个位于画布外的空占位蒙版，因此刚导入时不会改变任何像素。**保留占位蒙版，另画新蒙版；不要先删除唯一的占位蒙版**，否则整层会显现并影响整幅遮罩。关闭修补层或删除自己新增的修补蒙版，可恢复底稿效果。

修补层默认覆盖整个片段。只修某一帧时，将修补层入点/出点限定为该帧；修连续几帧时限定对应区间。人物运动需要为局部路径设置关键帧、跟踪或逐帧调整，不会自动把一帧的修补传播到整段。

遮罩使用已有RGBA的**Alpha通道**。查看预合成的Alpha通道可检查覆盖范围；只把RGB画成黑色不会自动擦除Alpha。也可解锁底稿后使用AE的Alpha画笔，但优先使用独立修补层，以便撤回和对照。原始像素轮廓没有整圈贝塞尔节点，只有你新增的局部修补路径可逐点编辑。

### 整个人物的边缘柔化与收缩

返回 **“MAD · 人物与Alpha修补 · …”** 合成，选中“01 整体边缘（效果控件）”，在AE的“窗口 → 效果控件”中调整：

| 控件 | 初始值与建议 |
| --- | --- |
| 边缘柔化（像素） | 默认0；可从1–2开始，数值越大过渡越软。负值按0处理 |
| 边缘收缩（正缩负扩） | 默认0；正数向内收缩，负数向外扩展。可从0.5–1的收缩量开始尝试 |

两项均支持关键帧，表达式将实际数值限制在AE原生效果支持范围内；超出范围时滑块输入仍显示原数值，渲染采用边界值。顺序固定为先收缩/扩展、再柔化，作用于底稿、补回和去除合并后的Alpha。默认值均为0，不自动修改原始边缘。最终颜色直接来自完整原画，不把整个人物RGB模糊。向外扩展会显示原画相邻区域，可能带回背景；细发梢或衣服线条应使用较小的柔化量。

局部修补工作区显示整体边缘处理前的彩色画面；整体柔化/收缩的最终效果在外层人物合成查看。两处各处理一类工作，不用手动替换白色层或搭建Alpha关系。若希望同时对照，可锁定外层合成查看器，再另开局部修补查看器并排查看。

新增其他Alpha效果时，可在外层“02 局部修补”图层的原有内部效果之后添加；保留该层和内部原画的关系，只会把处理后的Alpha用于最终画面。在控制空对象上随意添加图像效果不会处理人物。原生效果缺失/参数不兼容时脚本明确报错，按提示撤销本次导入；不要把派发成功当成导入已成功。

### 已有工程如何获得新入口

旧脚本和已导入的AE合成不会自动变成第二版。请用新版工具“从已有结果补导出 AE…”选择原任务manifest，以默认遮罩方式生成并发送新的JSX。新合成与旧合成并存，不重跑抠像，不改PNG，也不会覆盖AE里已经手工编辑的蒙版。

若旧合成已有修补，保留它作为对照；可在AE复制自己新增的完整蒙版（包含路径关键帧、羽化等属性），粘贴到新合成对应的补回/去除层。使用同一任务并保持图层起始时间一致；自己调整过的图层入出点也需要同步。确认新结果后再自行替换时间线中引用的旧合成。第二版报告及JSX载荷含有`script_version: 2`。

## 诊断与命令行

每次补导出有 `export_report.json` 和 `export_log.jsonl`。报告记录脚本版本、请求/实际方式、可用脚本、序列校验与脚本生成耗时；`script_layout`日志事件说明是否准备了彩色修补和边缘入口。矢量模式记录最大轮廓数、顶点数、累计顶点、所需路径槽，失败时记录可取得的片段内帧号（从0起）、秒数及轮廓信息。界面错误中的帧号从1起。日志不含图片数据、模型提示词或密钥。

导出目录有`INCOMPLETE.txt`或报告`status`不是`complete`时，不要把本次脚本视为完整交付；旧任务不受影响，可重新补导出。单个脚本派发成功不等于AE执行成功；脚本在一个撤销组内运行，发生部分导入时可在AE撤销一次。

```powershell
# 默认原画＋Alpha修补遮罩；只处理已完成的PNG结果。
.\MADSearcher-CLI.cmd cutout.export_ae --manifest-path 'E:\MADSearcher\MADSearcherTool\workspace\exports\cutout\某次任务\manifest.json' --ae-mode matte

# 同一入口还支持 --ae-mode rgba 或 --ae-mode paths。
# 新抠像任务也可通过 cutout.run --ae-mode matte 选择方式。
```

输出中的`ae_script`是建议发送的实际脚本；`ae_mode`为请求方式，`ae_actual_mode`为实际方式；`ae_scripts`列出所有成功准备的版本。CLI派发仍用`ae.send --script-path '返回的ae_script路径'`。
