# 姓名查询与排序（反馈13）

后续更新新增综合/台词/画面情节三种模式：本页的姓名规划和70/20/10规则继续用于场景通道；综合模式还会融合独立字幕结果，台词模式直接使用原始查询。独立字幕的补建和评分详见[台词检索与补建](台词检索与补建.md)。

本次调整发生在检索阶段，使用当前动画分组内的角色资料和已有字幕/画面向量。安装更新后可以直接重新搜索，不需要因为此次排序调整重新建立索引。原有素材、角色资料或模型变更导致的索引失效规则仍然适用。

## 怎样查询

可以直接输入“长崎素世请求丰川祥子不要离开”，无需在姓名旁加空格。假设当前分组保存了这两个姓名，且外观分别填写为“棕发女孩”和“蓝发女孩”，程序在本地生成：

| 通道 | 实际查询文本 | 用途 |
| --- | --- | --- |
| 原句 | 长崎素世请求丰川祥子不要离开 | 保留用户完整表达，参与融合及补充召回 |
| 情节 | 请求 不要离开 | 降低专名对情节相似度的干扰 |
| 外观 | （棕发女孩）请求（蓝发女孩）不要离开 | 用已填外观补充画面描述匹配，保留原句中人物出现顺序 |

这里没有让聊天模型改写问题，也没有生成新提示词。只有开启语义检索且存在兼容索引向量时，查询文本才会交给现有embedding接口。外观为空就保留该姓名，不猜测性别、发色或身份；整句没有可用外观时不生成该路。每次出现的外观最多180个字符，按整句2000字符预算进一步缩短外观，保留句末动作。

| 输入类型 | 处理方式 |
| --- | --- |
| “丰川祥子”“素世和祥子” | 优先已有角色出镜证据，其次姓名/别名文字提及；不请求查询向量 |
| “长崎素世请求丰川祥子不要离开” | 生成多路查询，以情节为主、人物证据有限加分；未识别身份的相关片段仍能入选 |
| “棕发女孩请求蓝发女孩不要离开”等未匹配姓名的查询 | 保留原来的文字与语义检索评分 |

关闭语义检索时，按已有字幕/画面描述做本地文字匹配，外观向量不参与。开启语义但缺密钥、没有兼容向量或接口失败时，会提示降级为本地关键词；纯姓名查询即使勾选语义也无需密钥。

结果上方显示匹配到的角色及情节文本；只有外观向量成功载入时才显示“已结合角色外观资料”。鼠标停在结果的匹配说明上可查看分数构成。“姓名文字提及”只说明文字出现过该姓名；“原句/外观补充”需要结合预览核对具体情节。

## 姓名识别与歧义

使用当前分组已保存的姓名和别名字典，Unicode NFKC及大小写归一后，按位置逐段采用最长匹配。英文名检查英文词边界，例如Ann不会匹配Annabelle；单字姓名/别名只匹配独立词项，避免从中文普通词中误抽取角色。

同名或同别名对应多个人物时，保留候选集合并提示有歧义，人物加分折半，也不挑一个人的外观改写查询。可使用已保存的更完整姓名减少歧义。程序不会通过作品常识自动补充未保存的别名。

## 组合查询分数

先计算情节文字分L和情节向量余弦相似度C。文字分沿用现有词项/中文字符对覆盖规则。L大于0或C至少0.22时，可由情节通道召回；其强度为：

```text
E_event = max(L, max(0, (C - 0.22) / 0.78))
```

为了保留情节短句遗漏的同义表达，外观向量相似度至少0.40或原句相似度至少0.55时，也允许补充召回。取通过各自门槛的最大相似度S，强度减半：

```text
E_fallback = 0.5 × max(0, (S - 0.22) / 0.78)
E = max(有效的 E_event, 有效的 E_fallback)，上限1
最终分数 = 0.70 × E + 0.20 × RRF + 0.10 × 人物证据
```

若补充证据更强，结果会标为“原句/外观补充”。所有通道都不满足时，即使人物ID完全匹配，也不入选。不同通道比较有效证据后取最大值，避免某路刚超过门槛就替换更强证据、反而降低情节强度。

RRF按每路排名融合：情节文字权重1、原句文字0.25、情节向量1、原句向量0.5、外观向量0.5；相同语义查询去重。仅使用有文字命中或向量相似度至少0.22的排名列表，同分并列。每路使用61/(60+名次)，加权后除以实际活跃通道权重总和，得到0到1之间的融合分。方法参考[微软对RRF的说明](https://learn.microsoft.com/en-us/azure/search/hybrid-search-ranking)；具体权重为本项目工程选择。

人物证据按所查询的角色组取平均：当前片段high为1、medium为0.55；歧义组的最强证据再乘0.5。多人物组合查询可参考前后各一个镜头、距离当前片段不超过5秒的实际采样证据，每侧至多检查6个子段，邻近权重再乘0.35。没有镜头元数据的旧索引不使用这项加分。相邻出镜不证明同框或动作关系，不会写入当前片段的出镜关联。

显式传入search.run的character_id仍严格要求当前片段关联该ID。界面的自然语言组合查询不作这种硬过滤，避免漏掉身份未知或正反打镜头。纯人物查询则采用max(0.9×直接人物强度+0.1×角色组覆盖率, 0.35×姓名文字覆盖率)，不套用组合查询的70/20/10公式。

## 请求与缓存

开启语义时，最多三条去重文本合并为一个embedding批次，接口自身仍可能按原策略重试。相较旧查询，一次新组合查询可能处理更多文本token；本次不发送画面或参考图，也不新增视觉分析请求。

向量缓存在workspace/cache/query_vectors，按模型及查询文本摘要寻址，最多256项、64MiB，淘汰最久未使用项。内容保存模型、摘要和向量，不保存查询原文或密钥，且目录不纳入Git。相同查询和模型可复用；缓存损坏或维度不兼容会重新获取，不能写缓存时保留当前结果并提示。查询模型必须与现有向量兼容，缓存不替代索引有效性检查。

## 当前边界与验收状态

此次降低了角色命中对组合查询的支配程度，但没有修改第12点的视觉身份识别。已有错误人物标签仍可能贡献少量加分；没有写入索引的情节，也不能保证靠排序找回。保留语序有助于表达谁请求谁，但当前没有独立的动作主语/宾语关系抽取器，仍需预览判断方向和情节。

分数、置信等级权重和阈值都是工程初值，不是身份概率、准确率或经过真实素材标定的指标。查询及排序代码、界面解释、待执行回归用例已完成；当前只做静态检查与构建发布，功能测试按用户要求延期。后续应对比同一段素材的姓名/别名/外观查询、角色误识别、正反打及同名歧义，再决定是否调整参数。
