# 台词检索与补建

独立台词索引用于搜索字幕原文、近似台词以及表达不同但意思相近的句子。它保存字幕单条文本与短上下文的向量，不加入人物外观、场景描述或角色名列表。现有画面索引继续保留；本次没有加入精排模型。

## 已有素材怎样使用

1. 启动更新后的 `artifacts/app/MADSearcher.exe`，在素材库选中对应视频。
2. 确认“外挂字幕”和“字幕偏移”正确。已经绑定的字幕会自动显示；可以选择新的SRT、ASS、SSA或VTT。
3. 勾选“建立字幕语义索引（OpenAI）”，确认设置中已填写密钥。
4. 点击 **“仅补建选中素材台词索引”**。它只解析字幕并补齐文本向量，不重新分析画面、不解码视频、不执行语音识别。
5. 搜索框右侧选择 **“台词”**，勾选 **“语义检索”**，再输入要找的句子。

例如，输入“你这个人满脑子都想的是自己呢”时，程序会把查询与字幕中的“你不管什么事 都只想着自己啊”直接做语义比较；不会要求两句话先通过字面重合门槛。这个例子对应的实际排序效果仍待后续功能验收。

补建完成后，素材卡片显示台词条数及“可语义检索”或“仅文字”。结果显示命中的字幕原句；鼠标停在正文上可查看原始时间、单条/短上下文和同时间的其他译文，停在匹配说明上可查看评分依据。没有视觉缩略图的素材也能返回台词结果，并可使用原有“生成预览”和导出功能。

未勾选“建立字幕语义索引”时，补建只保存本地文字及时间；之后仍需补建向量才能找同义表达。搜索时未勾选“语义检索”，或缺少密钥/兼容向量/接口失败时，使用文字匹配并提示原因。后台不会因输入了一句台词而自动付费重建索引。

## 三种搜索模式

| 模式 | 召回与排序 |
| --- | --- |
| 综合（默认） | 字幕独立召回与原有场景结果融合，完整字幕原文命中优先；同一时间附近的重复结果合并 |
| 台词 | 原始查询直接比较字幕，不按角色名字典去掉姓名；优先原文，结合字面与字幕语义评分 |
| 画面情节 | 使用原有片段文字/向量、姓名提取和人物证据排序，不加入独立字幕结果 |

画面情节模式复用现有片段向量，其中可能仍含建立索引时的字幕；该模式不表示已经重新生成纯画面向量。综合模式下，单独查询已保存姓名/别名仍沿用角色出镜证据规则，不用字幕向量猜测身份。若要搜索台词里提到的某个人名，请选择台词模式。

## 字幕单元和时间

每条字幕保留原始起止时间。ASS样式与文字类别用于分开组织字幕；同一条中出现中日等不同文字类别的换行会分开存储，同类换行保留在一起。这个规则不等于完整语言或说话人识别：纯汉字日语或混合语言仍可能被分到不理想的类别。

同一类别、同一字幕样式中，相邻2–3条可组成短上下文，间隔不超过2.5秒、总范围不超过20秒；明显重叠的不同台词不拼接。单条及上下文最多1600字符，长字幕拆成多个文本单元并共享该字幕的原始时间，不虚构更精细的时码。每个素材最多20000条处理后的字幕记录。

检索结果合并重叠译文及短上下文候选，保留得分最高的代表范围，并在 `dialogue_matches` 中保留其他命中原文及各自范围。它们不自动扩大为同框人物证据。零时长字幕在预览中补足至多0.1秒的可播放范围，返回的原始字幕时间仍保持不变。

## ASS特效字幕与条数上限

ASS文件的Dialogue行是显示事件，逐帧歌词和描边可能把一句话写成数千行。现在解析时先提取可见文本：按标签顺序识别 `\p` 绘图模式，丢弃绘图路径，保留 `\p0` 恢复后的文字。`\clip`、`\pos` 等样式不会使正文被误删；Comment、卡拉OK模板仍不导入。规则依据[Aegisub的ASS标签说明](https://aegisub.org/docs/latest/ass_tags/)。

同样式、说话人、文本、换行和时间的重复显示层会去重。带 `fx` 标记的同文连续事件可合并；没有该标记时，只有至少3条连续、每条大于0且不超过0.12秒的同文短事件才尝试合并。允许重叠或至多0.05秒间隔，保留最早开始和最晚结束。普通相邻重复对白、零时长普通字幕以及间隔较大的同句歌词保留各自时间，中日文译文不会互相合并。未标记特效采用保守的时长规则，并非完整ASS渲染或说话人识别。

20000条上限在绘图过滤、特效合并、有效文本分行和去重之后检查；原文件仍最多20MiB。无需手动删除OP/ED或切割字幕文件。若清理后确有超过20000条有效字幕，仍会明确提示拆分。程序只读取原字幕，不生成或覆盖它。

旧ASS/SSA独立台词索引会显示需要补建。选中对应视频，保留原字幕路径和正确偏移，点击 **“仅补建选中素材台词索引”** 即可；要搜索近义台词，保持 **“建立字幕语义索引”** 勾选。现有视觉索引不要求重建，SRT/VTT和ASR台词索引不受这次解析版本变更影响。未来手动建立完整索引时，清理后的字幕会参与片段分析缓存比较，内容改变的片段可能重新请求模型。

本次只完成静态检查与构建，尚未运行提供的第8集ASS的端到端补建；实际保留条数和检索效果以之后运行的日志和验收为准。

## 旧索引与独立更新

旧素材优先重新解析已绑定外挂字幕，恢复逐条时间。没有外挂字幕时，先复用已保存的台词记录，再尝试当前旧索引对应的ASR检查点；没有逐条数据时，可从旧片段字幕补建，但会明确标记“旧片段时码”。要恢复精确字幕时间，需要提供外挂字幕或在完整索引中重新转录；补建按钮本身不会启动ASR。

完整“建立 / 更新素材索引”也会保存独立台词记录；只有勾选字幕语义索引才额外生成台词向量，单独开启AI画面分析仍只生成原有片段混合向量。取消或失败时保留旧索引，已成功缓存的向量可供重试复用。

台词索引按视频文件、字幕文件及偏移校验有效性，修改角色资料或作品背景不会使它失效。更改原视频或字幕后，应更新相应索引。修改角色资料仍会使旧视觉索引失效，综合模式可能因此只显示仍然有效的台词结果。

数据库版本从2升级为3，首次打开前在 `workspace/backups/library_before_v3_*.sqlite3` 保存备份；新增独立字幕表，保留既有片段和视觉缓存。开发期间没有执行用户数据库迁移，升级将在后续启动使用新版本时发生。

## 向量请求、缓存与日志

补建先复用数据库中同模型、同文本的有效向量，再读取独立文件缓存，最后按32条一批补齐缺失向量。字幕内容未改变时不因角色资料或镜头切分变化而重新计算。变更embedding模型，或已有向量和缓存均不可用时，需要重新计算。

独立缓存位于 `workspace/cache/dialogue_vectors`，最多16384项、256MiB，按使用时间淘汰；查询缓存仍为 `workspace/cache/query_vectors`，最多256项、64MiB。缓存文件保存模型、文本摘要和向量，不保存密钥或查询/字幕正文，目录被Git忽略。缓存写入失败会提示，但不会丢弃已经取得的业务结果。

同一个查询向量可用于字幕和片段检索，要求模型及维度兼容。台词模式通常只需要一条查询文本；综合模式若有可用场景向量，可能生成第13项的原句、情节和外观变体，合并为一个批次。只有台词向量可用时，不额外生成无用途的情节/外观查询向量。

补建日志沿用 `workspace/logs/index`，包含 `subtitles.parse`、`dialogue.plan`、`dialogue.embedding`、`database.replace_subtitles` 及API请求阶段。`dialogue_index` 事件记录字幕条数、单元数、语义单元数，以及数据库/文件缓存复用和缺失计数。日志不输出台词正文、提示词、图片或密钥。API重试及实际usage沿用现有记录。

`subtitles.cleanup` 事件记录解析格式与清理版本、原始显示事件数（`raw_events`）、忽略的Comment数、纯绘图事件数（`drawing_only_removed`）、剔除的绘图片段数、重复层去重数（`duplicates_removed`）、特效合并减少数（`effects_merged`）、空文本数、时间范围外条数和最终有效字幕数（`effective_cues`）。`subtitles.parse` 阶段给出解析与清理的总耗时。发生清理时，完成提示也会显示数量摘要。

## 排序规则与验收边界

字面匹配归一Unicode、大小写、空白及标点；完整包含查询时文字分1，至少4个字母/数字字符的完整命中获得原文优先级。非完整中文匹配沿用相邻字符对覆盖，至少50%覆盖时计入文字分；英文也参考词覆盖。这些分数只衡量字面关系，不代表语义相似度。

字幕语义使用独立向量余弦相似度，初始候选门槛0.15。字幕文字和语义分别取最多 `max(60, 请求结果数×3)` 个候选，完整原文不因并列截断被提前丢弃。RRF按两个通道的名次融合，同分并列；相关强度为 `max(文字分, max(0, (余弦相似度−0.15)/0.85))`，台词分数为75%相关强度加25%RRF。

综合模式将字幕与场景两路的结果排名再次融合：65%较强通道分加35%两路RRF，完整字幕原文优先于这项分数。同时间重叠结果共享代表片段，原始字幕和场景评分分别保存在解释字段中。RRF方法参考[微软的说明](https://learn.microsoft.com/en-us/azure/search/hybrid-search-ranking)，具体比例及0.15门槛是本项目待标定的工程初值，不是准确率或概率。

当前只完成代码、静态检查和构建发布，功能测试按用户要求延期。尚未验证真实素材中的同义召回质量、否定/人物方向、迁移回归和交互表现。后续应同时使用原句、不同译文、分成多条的台词，以及意思相反但词汇接近的句子进行验收。本次不加入精排模型，不修改第12项视觉人物识别。
