# 抠像与创作输出边界

本模块使用 SAM 2.1（默认 tiny）对一个目标进行分割与时序传播。目标必须出现在所选片段的第一帧。模型结果是用于人工修补的初稿，不承诺还原透明特效、运动模糊、发丝半透明或遮挡后的身份。

## 输入

- 首帧蒙版：完整画布、尺寸与所选片段首帧一致；透明 PNG 的 alpha 或白色前景/黑色背景灰度图。禁止空蒙版、整幅前景、裁切过的图片及普通彩色参考照片。首帧原始 8 位 alpha 保留，传入模型时以 128 阈值二值化。
- 手动框：首帧像素坐标 `[左,上,右,下]`，框不可倒置或越界；完全在本地处理。
- 文字/参考图：OpenAI 只接收首帧与可选参考图，二者在外发前校正方向，保留原始分辨率并以JPEG质量95编码，使用detail:high；返回0–1000归一化目标框，再映射到原始坐标，后续分割在本地完成。本地SAM源帧及蒙版保留原始尺寸；抠像云端输入也不再应用512像素上限（仅索引使用该上限），模型服务端可能另有缩放规则。目标不存在或无法确定时明确停止。定位不是像素级分割；错选人物时应改用蒙版或手动框。
- 单次最多 120 秒、3600 帧、约 4K 像素。输出前按未压缩帧大小保守检查磁盘空间。
- 范围使用分钟:秒:帧，或显式源帧号；起点包含、终点不含，最少一帧。非整数帧率使用向上取整的标称帧率作非丢帧编号（23.976按24）；兼容小数秒输入，换算为最近一帧。120秒限制按选中帧数除以实际平均帧率计算。

## 内存与帧序

默认每块最多 32 帧。上一块末帧作为下一块首帧的蒙版提示，重叠帧只输出一次。块状态使用 CPU 缓存并在块完成后释放，避免整段 1024×1024 RGB float32 帧进入内存。CUDA 扩展和编译优化均不启用，适配原生 Windows 安装；使用 CPU 或 CUDA 推理。

源画面由 FFmpeg 按解码帧序选取为无损 PNG，再为 SAM 按块生成 JPEG。首帧预览使用相同源帧号。实际解码帧数必须等于选中帧数，缺帧时停止且不加载 SAM；媒体未提供总帧数时的估计值不作为解码成功证据。定位较后范围需顺序解码前面的画面。

导出的 RGBA 原 RGB 来自无损 PNG，alpha 是 straight/unpremultiplied。选中的每帧只输出一次，按源平均帧率播放为 CFR，不保留 VFR 的原始时间戳；分块边界可能降低时序一致性。第一帧以外的 SAM alpha 是 0/255 二值图。

## 输出目录

每次任务新建独立 `cutout_日期时间_随机标识` 目录，原素材只读，已有任务不覆盖。

| 文件或目录 | 用途 |
| --- | --- |
| `rgba/%06d.png` | 透明人物序列，保留完整画布与帧数，像素结果的主要依据 |
| `masks/%06d.png` | 与人物序列同步的 8 位灰度 alpha |
| `source_frames/%06d.png` | 与 mask 同步的完整原画面，用于 AE 原始图层；移动结果时必须连同保留 |
| `cutout_alpha.mov` | 可选 ProRes 4444，包含实际 alpha 平面，不含音轨 |
| `preview_checkerboard.mp4` | 棋盘背景的 H.264 预览，**不是透明视频**，不含音轨 |
| `ae_exports/ae_*/` | 独立AE导出目录，含RGBA/Alpha遮罩/可选矢量脚本、export_report.json及export_log.jsonl；旧import_cutout.jsx保留 |
| `manifest.json` | 仅在所有必需输出完成后写入；版本2记录源视频、半开帧范围、时间码、名义秒数、模型、尺寸、帧率、空前景帧和警告，不含 key |
| `INCOMPLETE.txt` | 任务未完成/被取消标记；有该文件时不要把输出当作完整结果 |

## AE 三种交接

默认matte（原画＋独立Alpha遮罩），另有rgba（透明PNG序列）和paths（可编辑逐帧矢量）。通过AE“文件 → 脚本 → 运行脚本文件”或AfterFX.exe -r执行JSX。先创建原尺寸/帧率结果合成，再放入当前合成的播放头；没有活动合成时打开结果合成，必要时延长目标合成。不会保存工程、改变项目色彩设置或重采样PNG，所有更改归入一次撤销组。

rgba直接读取现有RGBA并设置Straight Alpha；matte将完整source_frames与独立Alpha修补合成关联，Alpha来源是已有RGBA的透明通道，底稿锁定，补回/去除层初始为空。前两种不二值化、简化或重编码alpha，不受轮廓顶点限制。原始像素轮廓不能直接逐点拖动，但可以通过局部修补路径/画笔调整。补回可重新显示完整原画里被误删的内容。修补图层的操作和时间范围见[AE导出与修补](AE导出与修补.md)。

从已有任务manifest补导出时只读取所需PNG，检查完成状态、连续编号和图像头，不重新运行媒体/模型；每次新增ae_exports子目录，不改旧manifest或像素文件。移动时保留完整任务目录；新脚本使用相对路径。派发、脚本语法检查都不代表实际Adobe验证通过。

以下轮廓规则只适用于可选paths方式：

轮廓按嵌套深度使用 ADD / SUBTRACT / ADD，保留孔洞及孔洞内部岛。采用逐帧 HOLD 关键帧，允许顶点数量和组件数量变化。空帧和空路径槽使用画布外路径，保证人物不出现时不会露出整幅原画面。关闭该图层运动模糊和帧混合。

路径按像素中心提取并作0.75像素简化，不包含PNG中的半透明边缘。每帧最多64条轮廓，每条最多4096顶点，累计最多100万轮廓顶点，固定路径槽也最多64；均为本工具保护上限。三种脚本均支持1–99 fps。矢量超限、缺少OpenCV或处理失败时，记录失败原因并提供matte与rgba脚本，不增加简化容差、不删小组件或复杂孔洞。像素PNG仍为最终依据。

PSD 图层/矢量路径序列暂不实现。当前 JSX 是否在本机 AE 实际执行，以 `Docs/验收记录.md` 为准；脚本生成或文本检查不等于 Adobe 实际验证。

## 交互预览

抠像页原视频/结果分别提供可折叠的无声画面预览，长边最多640且可能进一步缩小；原图和输出尺寸不变。预览使用源解码帧序，结果使用已有RGBA帧序列；源视频首次远跳可能需要从头解码，之后连续预取与缓存播放。每面板缓存像素预算128MiB，内存缓存会淘汰且不跨重启保留。帧数为估计时，实际文件尾部仍以解码结果为准；VFR按平均帧率播放。操作流畅度、缓冲衔接及资源释放尚待后续功能验收。

抠像定位上传的预处理仍校验静态图片格式与2500万像素上限，输入最多100MiB、编码后最多32MiB；选择的参考图仍最多20MiB。超过容量时明确报错，不自动缩小分辨率。JPEG编码保留宽高而非无损像素值。
